# Controlled Experiment Loop v1 — Study-owned Execution Amendment

This amendment is normative for v1 together with the approved design and prior review amendment. Where this amendment conflicts with the earlier generic external Run registration API, this amendment wins.

## Decision

Controlled Experiment Loop v1 owns generation of the Run evidence that participates in a Study. It does not accept an arbitrary pre-existing favorable Run and attach it retrospectively.

Each Study also pre-registers a PPO seed policy with at least two unique non-negative seeds. One Study evidence point is therefore an immutable **EvidenceSet** containing one Run per registered seed, where only `ppo_seed` may vary across those Runs.

This is stronger than the earlier generic `register_run_evidence()` design and is adopted because it closes two material research risks:

1. selecting/attaching a Run after seeing its result;
2. treating one favorable PPO seed as stable evidence.

## S1. StudyPlan additions

`StudyPlan` MUST include:

```text
ppo_seeds
n_bootstrap
bootstrap_seed
```

Rules:

- `ppo_seeds` contains at least two unique non-negative integers;
- order is canonical and frozen by the plan;
- baseline config seed equals the first Study seed when the raw config contains a seed;
- `n_bootstrap` is positive;
- `bootstrap_seed` is non-negative;
- seed roster, bootstrap count, and bootstrap seed cannot be changed after Study creation.

The Study digest binds these values.

## S2. Study-owned EvidenceSet

An `EvidenceSet` consists of one verified PR1 Candidate Run per Study seed.

For seeds `(s1, s2, ...)`, every Run is generated from the same pre-resolved semantic config except:

```text
candidate_config.ppo_seed
```

which is replaced by the corresponding registered seed.

Every seed Run MUST:

- resolve through `evaluation.runs.config`;
- execute through `evaluation.runs.execute`;
- capture generation provenance through `evaluation.runs.provenance`;
- publish/load/inspect through `evaluation.runs.artifact`;
- use a research-context digest owned by the Study workflow;
- be stored under the append-only Study evidence namespace.

If any seed fails, the EvidenceSet is not partially published as valid evidence.

## S3. No external Run registration in v1

The earlier public `register_run_evidence`, `bind_baseline_evidence`, and `bind_candidate_evidence` operations are superseded for v1 Study workflow.

Standalone Run Core remains available outside a Study, but a Controlled Study does not admit an externally generated Run as baseline/candidate evidence.

The high-level v1 workflow becomes conceptually:

```text
create_study
run_baseline / create baseline EvidenceSet
define_experiment
run_experiment / create candidate EvidenceSet
verify_experiment
compare_experiment
decide_experiment
record_experiment_failure (when no complete candidate EvidenceSet exists)
freeze_study
inspect_study
```

Exact function names may follow the implementation plan, but the ownership rule is normative: Controlled Study evidence is generated by the Study workflow, not imported after observation.

## S4. Context binding

Study-owned execution still uses the prior `research_context_digest` protection.

- baseline seed Runs bind to a baseline execution context derived from the frozen Study plan;
- candidate seed Runs bind to the immutable ExperimentDefinition digest;
- the exact expected context is checked when EvidenceSet is loaded/verified.

A mismatched context is not accepted as controlled evidence.

## S5. Deterministic strategy seed invariance

For the current candidate suite, changing only PPO seed must not change deterministic strategies.

Across all seed Runs in one EvidenceSet, raw returns and relevant resolved evidence for these strategies MUST be exactly invariant:

```text
cash
constant_long
constant_short
trend
mean_reversion
ridge24
lightgbm24
```

Only `ppo` may vary with `ppo_seed`.

A deterministic-strategy difference across seed Runs is an integrity failure for the EvidenceSet, not research performance evidence.

## S6. Factor verification over EvidenceSets

The one-semantic-factor rule remains unchanged.

Baseline and candidate EvidenceSets must share the same seed roster. For controlled-delta verification, compare the frozen resolved semantic configs after normalizing only the within-EvidenceSet `ppo_seed` field according to the Study seed roster.

No-op factor changes remain invalid. Undeclared config/data/evaluation/provenance changes remain invalid.

The factor affected/unaffected strategy table from the prior review amendment still applies between baseline and candidate EvidenceSets.

## S7. Statistical evidence

The existing paired-return/bootstrap implementation remains authoritative.

For deterministic strategies, comparisons operate on the deterministic return series without pretending duplicate seed Runs are additional independent evidence.

For PPO:

- compare baseline/candidate using matched Study seeds;
- preserve seed-wise paired evidence;
- summarize seed robustness descriptively and using the existing seed-robustness primitive where applicable;
- do not manufacture one combined p-value across seeds;
- do not treat symbols sharing calendar shocks as independent samples.

Across symbols, retain per-symbol evidence plus descriptive positive/negative counts, medians, worst/best results, drawdown/cost/turnover summaries. No cross-symbol significance claim is introduced in v1.

## S8. FAILED attempt semantics

The prior terminal `FAILED` state remains.

If an Experiment is defined but Study-owned candidate EvidenceSet execution cannot complete before a trustworthy complete candidate EvidenceSet is published, the attempt may be recorded terminally `FAILED` with reason/actor/time. It remains budgeted and never enters lineage.

Once a complete candidate EvidenceSet exists, the attempt must proceed through controlled verification rather than being rewritten to FAILED.

## S9. Lineage and winner semantics

Lineage moves between EvidenceSets, not arbitrary individual seed Runs.

A later Experiment baseline may be:

1. the initial baseline EvidenceSet; or
2. a candidate EvidenceSet from a prior `ACCEPT_CANDIDATE` decision reachable from the initial baseline.

`WINNER` selects one candidate strategy from the selected accepted EvidenceSet. Controls are benchmarks only. If controls dominate or no candidate is supportable, freeze `NO_WINNER`.

## S10. Final-data boundary remains unchanged

Study-owned execution applies only to development evidence.

`trade_rl.evaluation.experiments` MUST NOT import or invoke sealed unused-future authorization. Study freeze remains the end of this subsystem.

## Additional Acceptance Criteria

v1 is not complete unless:

1. Study seed roster has >=2 unique non-negative seeds and is immutable;
2. EvidenceSet executes exactly one Run per registered seed;
3. only PPO seed differs within one EvidenceSet;
4. deterministic strategies are exactly invariant across seed Runs;
5. partial seed execution never publishes a valid complete EvidenceSet;
6. externally generated Run artifacts cannot be attached to a Controlled Study through public v1 workflow;
7. Experiment Definition exists before candidate EvidenceSet execution;
8. baseline/candidate EvidenceSets share the frozen Study seed roster;
9. PPO factor evidence is seed-matched and retains seed-wise results;
10. deterministic seed duplication is not treated as additional statistical evidence;
11. FAILED remains terminal/budgeted only before complete candidate EvidenceSet publication;
12. lineage and freeze operate on EvidenceSet identities;
13. sealed final-data authorization remains unreachable from the experiments package.
