# GPT向け handoff：Causal Alpha V10 r8〜r20

作成日: 2026-08-30 (JST)

## 1. 相談したい結論

目的は、Binance USDⓈ-M の各銘柄を同じ普遍モデルで扱い、各銘柄の long/short を独立に売買し、手数料・約定制約込みの after-cost 資産を最大化すること。全銘柄を同時に同じ方向へ持つことや、銘柄間の同時性を目的にはしていない。

ただし Selection は「全体が少し増えた」だけでは通さず、銘柄別 minimum/median、positive scope、CVaR、コスト、hard-risk を同時に評価している。r8 以降の正式 run はすべて Selection reject で、Admission/BC/RL は未実施である。

現時点の主な問題は、1分足不足よりも次の3点である。

1. hierarchical wave の実現エクスポージャが極端に少なく、entry target の多くが実約定ポジションにならない。
2. slow neutral、episode ownership、risk/no-trade execution の扱いが after-cost で弱い。
3. V9 は全体 net が正でも、銘柄別下振れと long/short 非対称が大きく、普遍戦略ではない。

## 2. 固定している設計・評価条件

- 実データは PostgreSQL/DB-backed Binance workflow。
- シミュレータは15分足。1分足は未導入。
- fast horizon は4時間、slow horizon は72時間。
- Signal → Selection → Admission → BC/RL の順序を維持。
- 報酬は `100 * net_log_return`。
- 銘柄IDを特徴量に入れず、universal model として学習。
- Selection は 9銘柄 × 8 scope × 3候補 = 216 replay leaf、paired scope は72。
- hierarchical wave は slow/fast confirmation、risk/liquidity cap、no-trade/execution contract を含む。
- ゲート閾値、holdout 分離、手数料計算は緩和していない。
- 期待するのは「どの銘柄でも勝てる」ことであり、特定銘柄の利益だけでは合格にしない。

## 6. 暫定解釈と GPT への質問

### 暫定解釈

1. r20 の flat-start split は provenance と初期状態を明示できたが、hierarchical wave の実現 exposure は依然として極端に少ない。
2. slow neutral の after-cost が負で、実行された rows も net が負。entry confirmation だけを緩めても解決しない可能性が高い。
3. r8〜r12 の候補比較から、boundary reset、neutral expiry、risk-breach flatten、fast-only ownership の単独修正は普遍的な資産増加を示さなかった。
4. V9 の balanced net 正は「全銘柄で勝てる」ことを意味しない。最低銘柄 net と positive scope が不合格である。
5. 15分足で execution/no-trade/risk/ownership の失敗が観測されているため、現時点で1分足へ移る根拠はない。1分足は intrabar 順序、約定遅延、volume participation の実証が得られた場合だけ比較候補にする。
6. Selection pass なしに Admission/BC/RL を実行しない現在の段階ゲートは維持すべき。

### GPT に判断してほしいこと

1. `slow neutral`、episode boundary、risk/no-trade を混ぜずに、次の事前登録候補をどの順序で設計すべきか。
2. 実現 exposure が極端に少ない場合、target compiler の entry floor/confirmation/hold ownership をどう再設計すべきか。閾値を単に緩めるのではなく、同じ Selection gate で比較できる候補にしたい。
3. long/short 独立売買を保ったまま、方向別 calibration・loss containment・position sizing を universal model にどう組み込むべきか。
4. 4時間 fast / 72時間 slow の組合せを、8時間〜7日程度の波に対してどう比較検証すべきか。変更する場合の事前登録候補と holdout 分離方法は何か。
5. 1分足を導入するために必要な実証条件（execution latency、intrabar ordering、volume participation、after-cost改善）をどう定義すべきか。
6. Selection が不合格の状態で、BC/RL を開始せずに次の学習サイクルへ進む最小の実験設計は何か。
